# Role & Context
You are a Staff Full-Stack Engineer and Clinical Workflow UX Specialist working on **MedBook AI** (`clinicflow`), a multi-tenant clinic management SaaS built with Next.js 15 (App Router), React 19, TypeScript (strict), Tailwind CSS 3.4, and Supabase[cite: 1].

# Objective
Add an **"Upload Document" (AI OCR)** action button inside the **Patient Waiting Queue** component (where the "Add Vitals" button currently resides)[cite: 1]. 

When staff/receptionists upload a patient's medical document (photo/PDF) directly from the queue:
1. It opens the OCR Upload Modal pre-bound to that specific patient's ID.
2. It processes the document using the AI OCR pipeline (`processDocumentOCRAction`).
3. It inserts detected medical history items into `patient_medical_history` with `source = 'ai_ocr'` and `verification_status = 'pending_approval'`.
4. It shows immediate visual feedback (toast + optional OCR status badge) on the queue card.
5. When the doctor later opens the patient record, these items are immediately ready for 1-click verification in the `HistoryTab` ribbon/cards.

# Backend & Action Workflow Integration

Ensure the server action `processDocumentOCRAction` (or `ocr-actions.ts`) handles queue-initiated uploads:
1. Receive `file`, `patient_id`, and `clinic_id`.
2. Extract clinical history items using LLM Structured Output.
3. Batch insert entries into `patient_medical_history` with:
   - `patient_id` = target patient UUID
   - `clinic_id` = active clinic UUID
   - `source` = `'ai_ocr'`
   - `verification_status` = `'pending_approval'`
   - `created_by_name` = `'Reception OCR Scan'`
4. Revalidate paths:
   - Revalidate `/app/dashboard` (or queue page) so queue card updates.
   - Revalidate `/app/patients/[id]` so history tab is updated when doctor opens chart.

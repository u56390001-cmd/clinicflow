## Expert Role
You are a Principal Software Security Architect specializing in Next.js 15 (App Router), React 19, TypeScript (Strict Mode), and Supabase Multi-Tenant Defense-in-Depth Security.

## Objective
Implement Phase 1 Application-Layer Security Guards for MedBook AI. Complement the existing database-level Row-Level Security (RLS) policies by adding server-side context validation, scoped service-role clients, automated API isolation tests, and architecture documentation.

## Technical Context & Rules
- **Framework:** Next.js 15 (App Router), Server Actions, React Server Components (RSC).

- **Goal:** Prevent unauthorized data access at the Application/Next.js Layer BEFORE queries hit the database.

## Deliverables & Implementation Specifications

### 1. `src/lib/auth/tenant-guard.ts` (Reusable Server-Side Guard)
Create a production-grade tenant validation helper for Server Actions and Route Handlers:
- **`requireClinicContext(requestedClinicId?: string)`**:
  1. Retrieves current authenticated user using `supabase.auth.getUser()`. If no session exists, throws `UnauthorizedError` (HTTP 401).
  2. Resolves `clinicId` either from the passed argument, dynamic route params, or request headers.
  3. Queries `clinic_members` to verify user belongs to the requested `clinicId`.
  4. Returns a typed `TenantContext` object:
     ```typescript
     export interface TenantContext {
       userId: string;
       clinicId: string;
       role: 'owner' | 'admin' | 'doctor' | 'receptionist';
       permissions: Record<string, boolean>;
     }
     ```
  5. If user is not a member of the clinic, throws `ForbiddenError` (HTTP 403: "Access Denied: Tenant Isolation Boundary Violated").

### 2. `src/lib/supabase/service-scoped.ts` (Service-Role Safety Wrapper)
Create a safe factory wrapper around the Supabase Service Role client to eliminate accidental cross-tenant data leaks:
- **`createScopedServiceClient(clinicId: string)`**:
  - Requires `clinicId` as a mandatory parameter.
  - Automatically injects `.eq("clinic_id", clinicId)` or validates `clinic_id` on all CRUD operations executed via this client.
  - Throws an explicit runtime error if instantiated without a valid `clinicId` string.

### 3. `scripts/rls-api-test.ts` (Automated API Isolation Test Runner)
Create an automated TypeScript script (executable via `npx tsx scripts/rls-api-test.ts`) that verifies application-layer security guards:
- Mocks API requests / Server Action calls from `User_A` attempting to access resources with `Clinic_B_ID`.
- Asserts that `tenant-guard.ts` intercepts the request and throws an HTTP 403 error BEFORE making a database call.
- Validates that legitimate requests from `User_A` with `Clinic_A_ID` resolve successfully.
- Output clean terminal report: `[PASS] App-Layer Cross-Tenant Blocked`.

### 4. `docs/SECURITY_MODEL.md` (System Security Architecture Document)
Write a comprehensive Markdown security specification detailing the MedBook AI multi-tenant defense strategy:
- **Layer 1:** Next.js Edge Middleware & Route Protection.
- **Layer 2:** Application-Layer Guards (`tenant-guard.ts` & `service-scoped.ts`).
- **Layer 3:** Database PostgreSQL RLS, Composite Foreign Keys, and Security Definer Functions.
- **Incident Response & Audit Checklist:** Procedures for verifying zero data leaks during CI/CD deployments.

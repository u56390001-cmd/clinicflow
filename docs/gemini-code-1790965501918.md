### File 2: `utils/audioAnnouncer.ts`
Implement robust audio notification functions:
1. `playDigitalChime()`:
   - Uses `window.AudioContext` or `webkitAudioContext` to synthesize a pleasant two-tone digital chime (e.g., 523.25Hz [C5] transitioning to 659.25Hz [E5]) using Sine wave oscillators.
   - Requires NO external MP3/audio files to ensure 100% reliability offline or on slow networks.
2. `speakAnnouncement(tokenNumber: string | number, patientName: string, doctorName: string, roomNumber?: string)`:
   - Checks if `window.speechSynthesis` is supported.
   - Cancels any ongoing speech instances (`speechSynthesis.cancel()`).
   - Builds speech text: `"Token Number ${tokenNumber}, ${patientName}, please proceed to ${doctorName}'s consultation room ${roomNumber ? roomNumber : ''}"`.
   - Sets speech rate to `0.85` (clear, understandable pace for public address).
3. `triggerQueueCallout(...)`:
   - Sequentially calls `playDigitalChime()`, waits 600ms, and then triggers `speakAnnouncement()`.

---

### File 3: `hooks/useQueueSocket.ts`
Create a custom React hook `useQueueSocket(clinicId?: string)`:
- Manages connection status (`isConnected`, `reconnecting`, `error`).
- Subscribes to room `clinic:{clinicId}:queue` (or fallback default channel).
- Maintains local `queueState` initialized with realistic fallback mock data for testing.
- Listens for `QUEUE_UPDATED` WebSocket events.
- When `payload.tokenChanged` is `true`, calls `triggerQueueCallout()` automatically if audio is unlocked.
- Features automatic reconnection logic with exponential backoff on disconnects.

## 1. Database Architecture (`telehealth_sessions`)

Create a database migration (`supabase/migrations/20261015_telehealth.sql`) establishing the `telehealth_sessions` table with strict Row-Level Security (RLS) to prevent cross-tenant data leaks.

```sql
CREATE TYPE telehealth_status AS ENUM ('SCHEDULED', 'ACTIVE', 'COMPLETED', 'CANCELLED');

CREATE TABLE telehealth_sessions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    clinic_id UUID NOT NULL REFERENCES clinics(id) ON DELETE CASCADE,
    doctor_id UUID NOT NULL REFERENCES doctors(id) ON DELETE CASCADE,
    patient_id UUID NOT NULL REFERENCES patients(id) ON DELETE CASCADE,
    appointment_id UUID REFERENCES appointments(id) ON DELETE SET NULL,
    room_id TEXT NOT NULL UNIQUE,
    status telehealth_status NOT NULL DEFAULT 'SCHEDULED',
    started_at TIMESTAMPTZ,
    ended_at TIMESTAMPTZ,
    patient_join_url TEXT NOT NULL,
    created_at TIMESTAMPTZ DEFAULT now(),
    updated_at TIMESTAMPTZ DEFAULT now()
);

-- Row-Level Security (RLS)
ALTER TABLE telehealth_sessions ENABLE ROW LEVEL SECURITY;

-- Policy: Clinicians and staff can only access sessions belonging to their tenant clinic
CREATE POLICY "Tenant Isolation Policy for Telehealth Sessions"
ON telehealth_sessions
FOR ALL
USING (clinic_id = (SELECT clinic_id FROM clinic_members WHERE user_id = auth.uid()));

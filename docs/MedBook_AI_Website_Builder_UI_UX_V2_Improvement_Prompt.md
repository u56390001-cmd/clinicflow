# MedBook AI — Website Builder UI/UX Improvement Prompt
## Design System V2 • Clinic Website Builder • Desktop / Tablet / Mobile

> **Role:** You are a senior product designer + frontend architect working inside the existing MedBook AI codebase.
>
> **Primary objective:** Improve the existing Website Builder UI/UX substantially without breaking its current functionality, data flow, editor behavior, website rendering, publishing, custom-domain flow, AI-agent integration, doctor/service data, or existing architecture.
>
> **Important:** This is an **existing production-style SaaS feature**. Do NOT blindly rebuild it from scratch. First understand the existing architecture and then improve the UI/UX around it.

---

# 1. PRODUCT CONTEXT

MedBook AI is a healthcare practice-management SaaS.

Each clinic can use the **Website** module to:

- Build its own public clinic website.
- Edit/reorder/hide/show website sections.
- Edit clinic information.
- Display doctors dynamically.
- Display services dynamically.
- Display booking information dynamically.
- Display clinic/contact information dynamically.
- Use AI Agent / clinic data inside the website.
- Customize the website's visual appearance.
- Upload/manage images.
- Configure SEO.
- Connect a custom domain.
- Publish the website and make it live.

The Website Builder is therefore not merely a page editor. It is a **clinic website management workspace**.

The UI must feel like a serious modern SaaS product used daily by clinic administrators — not like a generic website template editor.

# 3. CURRENT BUILDER — MAIN UX PROBLEMS TO SOLVE

The current builder uses roughly:

**Left:** page sections  
**Center:** editing controls  
**Right:** website preview

This basic architecture is good and SHOULD remain unless the existing code proves a better structure is necessary.

However, the current workspace has several UX problems:

### 3.1 Excessive visual competition

Content, Design, Images, Widget, SEO and Domain compete for attention.

Create clearer hierarchy between:

- Page structure
- Content
- Appearance
- Media
- Functional components
- SEO
- Publishing/domain

### 3.2 Section navigation needs stronger hierarchy

The left panel currently mixes:

- section list
- ordering controls
- visibility controls
- section search
- hidden sections

Make these relationships much clearer.

### 3.3 Editing area needs better grouping

Do not make the user scroll through a long undifferentiated form.

Group fields into logical sections such as:

- Section visibility
- Content
- CTA
- Media
- Layout
- Advanced settings

Use progressive disclosure where appropriate.

### 3.4 Preview needs to feel like a real device

The preview should clearly communicate:

- Desktop
- Tablet
- Mobile

Users should be able to switch viewport modes intentionally.

The preview must never feel like a random narrow browser column.

### 3.5 Header controls need better placement

Global actions should be separated from editor controls.

Recommended hierarchy:

**Workspace identity**
→ page/site status
→ editing tools
→ preview controls
→ save state
→ publish

Avoid placing unrelated actions beside each other.

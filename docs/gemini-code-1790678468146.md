# Role & Context
You are a Staff Full-Stack Engineer and AI Integration Specialist with expertise in Next.js 15 (App Router), React 19, TypeScript (strict), Supabase (Postgres, Row-Level Security, Server Actions), and LLM Structured Outputs (Gemini / OpenAI API / Vercel AI SDK)[cite: 4].

You are working on **MedBook AI** (`clinicflow`), a multi-tenant clinic management SaaS[cite: 4]. 

# Objective
Implement the backend and frontend ingestion workflows for **Patient Pre-Intake Forms** and **AI OCR Medical Document Parsing**. 

These two workflows will write entries into the `patient_medical_history` database table with:
- `verification_status = 'pending_approval'`
- `source = 'patient_intake'` OR `source = 'ai_ocr'`

This connects directly to the newly built `HistoryTab` UI and migration `0048_structured_medical_history.sql`, enabling the 1-click doctor verification workflow[cite: 4].

# Data & Database Architecture Context

### Database Target (`patient_medical_history` table):
- `patient_id`: UUID (FK to `patients.id`)[cite: 4]
- `clinic_id`: UUID (FK to `clinics.id`)[cite: 4]
- `category`: Enum/CHECK (`past_illness` | `surgery` | `hospitalization` | `family_history` | `lifestyle` | `immunization`)
- `condition_name`: text (e.g., "Hypertension", "Appendectomy")
- `onset_date`: text nullable (e.g., "2018", "Childhood")
- `clinical_status`: text (`active` | `resolved` | `chronic`)
- `source`: text (`patient_intake` | `ai_ocr`)
- `verification_status`: text (`pending_approval`)
- `relationship`: text nullable (for `family_history`, e.g., "Father")
- `created_by_name`: text nullable (e.g., "Patient Pre-Intake Portal", "AI OCR Scanner")

# Scope of Deliverables

## Module 1: Patient Pre-Intake Ingestion (`submitPatientPreIntakeAction`)
1. Create Server Action `lib/actions/patient-intake-actions.ts`:
   - Validates public/token-protected patient form submission with Zod schema (`lib/validation/intake-schema.ts`).
   - Extracts medical history items filled out by the patient.
   - Inserts each item into `patient_medical_history` setting `source = 'patient_intake'`, `verification_status = 'pending_approval'`, and `created_by_name = 'Patient Pre-Intake'`.
   - Revalidates path `/app/patients/[id]` (or clinic patient record route).

2. Create/Update Patient Pre-Intake Endpoint or Public Form Component (`app/(public)/intake/[token]/page.tsx`):
   - Simple, mobile-friendly intake form collecting past conditions, surgeries, and family history.
   - Triggers `submitPatientPreIntakeAction`.

---

## Module 2: AI OCR Medical Document Parser (`processDocumentOCRAction`)
1. Create AI Parsing Service / Server Action `lib/actions/ocr-actions.ts`:
   - Accepts an uploaded document file / image URL (Prescription scan, Lab report, or Discharge summary).
   - Sends image/PDF to LLM structured output parser (e.g., Gemini Vision / OpenAI structured output / Vercel AI SDK `generateObject`) with a strict Zod schema matching `HistoryItem` categories.
   - System Prompt Instructions for LLM:
     > Extract all past illnesses, surgical histories, hospitalizations, family medical histories, and immunizations from the clinical document. Standardize item names, extract dates/years if present, and assign clinical status (`active` | `resolved` | `chronic`).

2. Save AI Extracted Results:
   - For every extracted item, batch insert into `patient_medical_history` with:
     - `source = 'ai_ocr'`
     - `verification_status = 'pending_approval'`
     - `created_by_name = 'AI OCR Scanner'`

3. OCR Modal / Upload Component (`components/patients/record/ocr-upload-modal.tsx`):
   - Drag & drop image/PDF upload modal in the Patient Record view.
   - Shows parsing spinner / progress state.
   - On completion, triggers toast notification ("Extracted X history items for review") and refreshes `HistoryTab` data.

# Context & Tech Stack
You are a Staff Full-Stack Engineer and Healthcare SaaS Architect working on **MedBook AI** (`clinicflow`), a multi-tenant clinic management platform built with Next.js 15 (App Router), React 19, TypeScript (strict), Tailwind CSS 3.4, and Supabase (Postgres with RLS)[cite: 1].

# Comprehensive Objective
Implement an end-to-end **Centralized Document Ingestion Workflow** from the Waiting Queue/Appointment view that automatically routes extracted AI OCR data across multiple patient tabs, and update the **Overview Tab** (`components/patients/record/tabs/overview-tab.tsx`) with structured **Active Medications** and **Recent Lab Reports** cards[cite: 1].

# PART 1: Queue Ingestion & Multi-Tab Routing Engine

## 1. Waiting Queue UI Integration
- In the queue card component (e.g., `components/queue/queue-item-card.tsx` or `components/dashboard/waiting-queue.tsx`):
  - Next to `[+ Add Vitals]`, add an **`[Upload Doc]`** button[cite: 1].
  - **Styling**: `inline-flex items-center gap-1.5 px-2.5 py-1.5 rounded-[8px] text-xs font-medium border border-hairline bg-white hover:bg-slate-50 text-ink transition-colors`[cite: 1].
  - Icon: `UploadCloud` / `FileText` from `lucide-react`.
  - Clicking this opens `OcrUploadModal` pre-populated with `patient_id` and `clinic_id`.
- **Queue Feedback**: After upload, display an inline status pill on the queue card: `[📄 1 Doc Scanned · Pending Review]` (`bg-amber-50 text-amber-700 border border-amber-200 text-[10px] px-2 py-0.5 rounded-full`).

## 2. Server Pipeline & Multi-Tab Data Distribution (`lib/actions/ocr-actions.ts`)
When a PDF or image document is uploaded, execute `processDocumentOCRAction`:
1. **Documents Tab Storage**: Save the raw file to Supabase Storage and insert a record into `patient_documents` (`file_url`, `file_name`, `uploaded_by`, `patient_id`, `clinic_id`).
2. **AI OCR Parsing**: Process the document using Structured AI Output and distribute extracted findings across three tables:
   - **Past Illnesses / History**: Insert entries into `patient_medical_history` (`verification_status = 'pending_approval'`, `source = 'ai_ocr'`) -> *Feeds `HistoryTab`*.
   - **Active Medications**: Insert entries into `patient_medications` (`status = 'active_pending'`, `source = 'ai_ocr'`) -> *Feeds `PrescriptionsTab` & `OverviewTab`*.
   - **Lab Results / Vitals**: Insert entries into `patient_lab_results` (`parameter_name`, `observed_value`, `unit`, `reference_range`, `status`, `source = 'ai_ocr'`) -> *Feeds `OverviewTab` & `DocumentsTab`*.
3. **Revalidation**: Trigger `revalidatePath('/app/dashboard')` and `revalidatePath('/app/patients/[id]')`.

# PART 2: Overview Tab UI Updates (`overview-tab.tsx`)

Enhance `components/patients/record/tabs/overview-tab.tsx` with two structured summary components[cite: 1]:

## 1. Active Medications Card
- Display current ongoing medicines for the patient.
- **Item Fields**: Medicine Name & Strength, Dosage & Frequency (e.g., *1 Tab - BD*), Start Date/Duration.
- **Source Badges**:
  - `Prescribed`: `bg-teal-50 text-teal-700 border-teal-200`
  - `Pre-Intake`: `bg-blue-50 text-blue-700 border-blue-200`
  - `AI OCR`: `bg-amber-50 text-amber-700 border-amber-200`

## 2. Recent Lab Reports & Diagnostic Findings Card
Place this card **directly below** the Active Medications card.

- **Header**: Icon (`FlaskConical`) + Title `"Recent Lab Reports & Key Readings"` + Action button `[View All Documents →]` (switches tab to `documents-tab.tsx`).
- **Structured Findings Table**:
  - Grouped by Report Name & Date (e.g., *"CBC Report — 24 Sep 2026"*).
  - Table Columns: `Parameter` (e.g., HbA1c, Fasting Glucose), `Observed Value & Unit` (e.g., `7.4 %`), `Reference Range` (e.g., `< 5.7%`), and `Status Badge`:

    - `Abnormal/High/Low`: `bg-rose-50 text-rose-700 border-rose-200 font-semibold`

- **Document Preview Action**: Include an `[Eye]` icon button on each lab report row to open a quick modal preview of the original scanned PDF/image without leaving the Overview tab.
